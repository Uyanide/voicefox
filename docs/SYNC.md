# VoiceFox 同步说明

VoiceFox 的跨音源同步使用独立的同步层，不把同步逻辑塞进具体音源实现。

## 当前架构

```
UI / SyncOverlay
    ↓
app::sync
    ↓
lx-core::sync::SyncEngine
    ├── matcher
    ├── SyncPlan / Diff
    └── execute
    ↓
lx-source::sync::SyncProvider
    ├── 网易云音乐
    └── QQ 音乐
```

新增音源时，原则上只需要实现 `SyncProvider`，匹配器和核心执行逻辑保持不变。

## 匹配优先级

1. ISRC
2. 同平台歌曲 ID
3. 标题 + 歌手 + 专辑精确元数据
4. 标题/歌手元数据 + 时长
5. 模糊元数据匹配
6. 无法匹配

默认时长容差为 5 秒，模糊匹配阈值为 92。
## 当前策略：网易云远程集合只读镜像

网易云歌单**不再复制成本地歌单**，也不再向远端推送。同步 = 把账号里的歌单
（含「我喜欢的音乐」）连同歌曲元数据读进一个**远程集合缓存**：

- 缓存按歌单 id 增量合并；只有远端结果完整时才整体替换，远端删掉的歌单才会消失。
- 只要有一个歌单没拉到（例如被频控），就退化为增量合并，失败歌单保留缓存里的旧数据。
- 缓存落盘在数据目录下的 `netease_collections.json`，重启后歌单页仍然是用户的
  歌单，不会悄悄退回公开的「热门歌单」列表。
- 歌单页在缓存就绪时以缓存为唯一数据源；播放仍走网易云音源自己的地址解析。
- 「我喜欢的音乐」靠 `specialType == 5` 识别，与歌单名称无关（用户可以随时改名，
  按名称匹配会在改名后失效）。
- 预览页只说明「会读到什么、缓存会怎么变」，不再声称会把本地歌单上传到网易云。

QQ 音乐尚未接入这一模式：设置页按 Q 会明确提示暂不支持，而不是静默无响应。

## 两个必须知道的接口坑

1. `api/v3/playlist/detail` 的 `playlist.tracks` 对**收藏来的**（非本人创建的）
   歌单只返回前 20 首，且 `n` 参数已被服务端忽略（实测 `n=1000` 与 `n=100000`
   都只给 20 首）。完整列表在 `playlist.trackIds`，歌曲详情需要分批用
   `api/v3/song/detail` 补全。实现见 `source/src/wy/playlist.rs` 的
   `get_detail` / `songs_from_detail`。
2. 请求过密时网易云返回 **HTTP 200 + `code=405`、`message=操作频繁，请稍候再试`**，
   响应体里 `playlist` 为空。它必须被当成「失败」而不是「这个歌单是空的」，
   否则空歌单会被写进缓存。见 `get_json` 里的退避重试。

## 当前音源

| 音源 | 登录 | 预览 | 读入远程缓存 | 写回远端 | 收藏同步 |
|---|---|---|---|---|---|
| 网易云音乐 | 扫码 | ✓ | ✓ | 接口保留，UI 未接入 | ✓ |
| QQ 音乐 | 扫码 | — | — | 接口保留，UI 未接入 | — |

`lx-core::sync` 的双向匹配与执行引擎、以及各音源的 `SyncProvider` 写入实现
（`add_songs` / `remove_songs` / `create_collection`）都还在，但当前 UI 走的是
上面这条只读路径。原先 `Storage` 里持久化本地↔远端歌单映射的
`sync_playlist_mappings.json` 已随本地复制模式一起移除。
## 网易云登录注意事项

网易云扫码登录已经加入：

- 二维码生成与轮询；
- 登录成功后的 Cookie 收集；
- 风控/验证状态识别（`QrLoginStatus::RiskControl`）；
- 登录会话失效后的错误传播。

登录走的是公开接口（`/api/login/qrcode/*`），主机按
`interface.music.163.com` → `interface3.music.163.com` → `music.163.com`
顺序回退（三者接口相同、IP 不同，只认一个域名时单机抽风就表现为"生成二维码
失败"）。**没有可用的会话续期接口**：实测 `api/login/token/refresh` 返回
`code=400`、`api/login/refresh` 返回 `code=404`。因此 `wy::login::refresh()`
实现为「会话有效性探测」而不是「延长会话」——`MUSIC_U` 一旦过期就只能重新
扫码。需要真正的续期就必须改回 eapi 登录（`crypto::eapi` 仍在，lyric 接口在
用），这是一个有意的取舍，不要把它当成 bug 去"修"。

但是，**“代码层登录流程通过测试”不等于网易云官方风控一定允许扫码登录**。

实际测试中，如果手机网易云显示：

> 检测到当前设备环境异常，本次操作已拦截

这表示网易云服务端拒绝了当前登录环境。它不是 VoiceFox TUI 渲染错误，也不能通过单纯增加轮询重试解决。

遇到这种情况：

1. 不要连续重复扫码；
2. 等待网易云风控限制解除后再测试；
3. 可先用官方网易云客户端/网页确认账号本身正常；
4. 再使用 VoiceFox 做单次扫码验证；
5. 如果仍然被拦截，需要继续调整网易云登录请求的客户端环境，而不是把它标记为“登录成功”。

## 验证

同步核心目前有匹配器单元测试，覆盖：

- 同平台 ID 优先；
- 跨平台精确元数据匹配；
- 明确识别未匹配歌曲。

网易云二维码状态映射也有单元测试。

真实账号的扫码登录、远端歌单写入和收藏写入属于网络端到端测试，不能由离线单元测试替代。
## 数据安全与同步原则

同步不会把账号密码写入同步数据。

平台登录态仍由各音源自己的会话存储管理。同步映射只记录本地歌单与远端歌单之间的关联，不保存远端账号密码。

在执行同步前，建议先查看 Diff；对无法匹配的歌曲，不会强行用低置信度结果替换。

## 后续工作

当前同步层已经具备扩展到更多音乐平台的基础。后续重点包括：

- 设置页提供稳定、可见的“账号与同步”入口；
- 完善歌单级 Diff 明细和确认流程；
- 更完整的未匹配处理；
- 登录刷新与失效后的重新登录提示；
- QQ 音乐真实账号端到端验证；
- 更多音源的 `SyncProvider` 实现。
