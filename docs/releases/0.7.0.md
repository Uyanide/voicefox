# VoiceFox 0.7.0

## 版本概览

这一版的主角是 **修复 issue #44**：Windows 上导入 lx-music JS 音源（无论 URL
还是本地文件）必报「JS 引擎子进程已退出」—— 根因是启动 Node 子进程前把环境
变量清得只剩 `PATH`/`HOME`/`USERPROFILE`，而 Windows 的 `node.exe` 没有
`SystemRoot` 根本起不来。本版把它修掉，并且失败时能说出**真正的原因**。

第二件事是一次**默认行为变化**：播放地址解析从「JS 音源优先」改为
**「内置音源先行，JS 作为回退」**—— 一个挂死的 JS 脚本曾让酷我、网易云这些
本可直接播放的歌一起变慢；依赖 JS 音源解 VIP 曲目的用户可以用新配置
`[source] js_first = true` 恢复旧行为。

版本号走到 **0.7.0**（新增用户可见功能）：QQ 音乐歌单只读镜像、ListenBrainz
听歌记录上报、macOS 系统媒体控件（Now Playing）都是这一版进来的。

---

## 一、Windows 上 JS 音源子进程秒退（修复，issue #44）

导入链路 `load_source_with_policy → JsEngine::new → node wrapper.js <音源> →
ping()` 里，子进程一启动就退出、stdout 一行 JSON 都没读到，于是只剩一句
「JS 引擎子进程已退出」；加载器还把这个确定性错误重试 3 次，用户看到的最终
报错是「已重试 3 次」。`node --help` 探测用的是完整环境，所以「本机 node
正常、VoiceFox 里必挂」。五处修复：

- **环境白名单补全**：Windows 下按白名单放行 `SystemRoot` / `SystemDrive` /
  `TEMP` / `TMP` / `PATHEXT` / `ComSpec` / `APPDATA` / `LOCALAPPDATA` /
  `USERPROFILE` / `HOMEDRIVE` / `HOMEPATH` / `PATH`（`node.exe` 靠
  `SystemRoot` 初始化 SXS / CryptoAPI / Winsock）。白名单里的键互不为大小写
  变体——Windows 环境块大小写不敏感，重复键会让 `CreateProcess` 失败。
  `NODE_OPTIONS` / `NODE_PATH` 仍然故意排除，注入面不变。
- **`--allow-fs-read` 路径归一**：Windows 路径统一转正斜杠再交给 Node 的
  权限树（反斜杠路径作为目录前缀授权时经常对不上，`readFileSync` 直接
  `ERR_ACCESS_DENIED`）；并追加音源文件所在目录的带尾斜杠前缀授权，
  脚本用 `__dirname` 读同目录资源不再被拒。
- **stderr 留尾**：子进程 stderr 保留最后 8KB。ping 失败、初始化失败、
  stdout 通道断开时，错误消息拼上**退出状态码 + Node 输出**，
  不再是一句空的「已退出」。
- **协议输出同步刷**：`wrapper.js` 的 JSON Lines 输出从
  `process.stdout.write` 改成 `fs.writeSync(1, ...)`——前者是异步的，
  紧跟的 `process.exit` 会把还没刷出的 `initError` 整个丢掉，
  这正是初始化失败被记成「已退出」的另一半原因。
- **重试只留给网络**：下载错误分两类——网络类瞬时错误（请求失败、传输中断）
  最多重试 3 次；HTTP 状态码、大小超限、内容为空、本地文件读取失败、
  完整性校验失败都是确定性失败，**立即返回**。JS 引擎启动失败同样不再重试，
  「已重试 3 次」不会再盖住真正的原因。失败后恢复上一份可用脚本的逻辑保留。

**如果你是那位报 #44 的 Windows 11 用户：请更新后重新导入一次音源。**
若仍失败，新的报错会带上退出码和 Node 的 stderr 原文，把它贴进 issue 即可。

## 二、播放地址默认「内置音源先行」（行为变化）

在线歌曲的解析顺序从「JS 音源（配置顺序）→ 内置原平台」改为
**「内置原平台 → JS 音源 → 跨平台兜底」**：

- JS 音源搜到的歌（`SourceId::Local` + `extra["source"]` 平台标记）同样内置
  先行；平台标记映射表从 5 个平台补齐到**全部 12 个内置音源**
  （千千接受 `bd`/`baidu` 别名、汽水接受 `qishui`/`douyin`，大小写不敏感），
  哔哩哔哩、千千、JOOX、汽水、5sing、Jamendo、Apple 的搜索结果在 JS 失败后
  能回到已经写好的内置实现，不再直接报「未加载任何 JS 音源」。
- 播放失败后的换源重试语义不变：内置先行模式下某首歌确实要靠 JS 解析时，
  JS 音源仍按配置顺序逐个参与；mpv 播放失败后从下一个 JS 音源继续，
  不重复请求已经失败过的内置音源。
- **想恢复旧行为**：配置文件 `[source]` 下加 `js_first = true`。
  解析策略（`policy` = auto / prefer / only）语义不变，与这个开关正交。

同时把 JS 脚本缓存目录从 `~/.config/lx-tui/sources` 迁到
`<配置目录>/voicefox/sources`：数据目录早已统一叫 voicefox，旧目录导致用户
按文档备份时带不走音源。首次使用时自动把旧目录内容搬过来（绝不覆盖新目录
已有文件，搬空后清理旧目录）。

## 三、QQ 音乐歌单只读镜像（新）

设置页按 `Q` 之前只回一句「暂不支持」。QQ 音乐的 `SyncProvider` 和扫码登录
其实早已就绪，这次把 app 侧的只读镜像管线放开到 QQ：

- 与网易云同一条管线、同一套策略：拉取账号歌单（含「我喜欢」，固定 id `201`）
  连同歌曲元数据读进**远程集合缓存**；失败不覆盖、只读、不写远端。
- 缓存按平台分槽：网易云 `netease_collections.json`、QQ 音乐
  `qq_collections.json`，互不干扰；设置页「数据与本地库」的清理入口改为
  一次清空全部镜像。
- 可见的入口全部接上：设置页「远程歌单镜像」窗口与内嵌列表（每行带
  `[网易云]` / `[QQ音乐]` 平台标签）、歌单页「我的歌单」（QQ 歌单用
  `qq-account:` 虚拟 id，播放仍走 QQ 音源自己的地址解析）、
  **收藏页的 QQ 音乐标签页**（红心来自镜像缓存）。
- 扫码登录 QQ 成功后自动触发一次镜像刷新，与网易云登录后的行为一致。
- **写回仍未开放**：QQ 的推送写回适配器（新建歌单 / 追加歌曲）已实现，
  但尚未按网易云的标准完成真实账号端到端验证；推送入口仍只开放网易云。
  详见 [`SYNC.md`](../SYNC.md)。

## 四、ListenBrainz 听歌记录上报（新）

配置 `[integration] listenbrainz_token` 填入用户 token
（listenbrainz.org 头像 → User Profile 页可见）后，每首歌**开始播放满 30 秒**
向 ListenBrainz 提交一条 listen（submit-listens API）：

- 切歌、暂停、停止都会让这次上报静默作废；缺歌名/歌手的记录本地直接跳过。
- 尽力而为：失败只记日志，不做本地排队重发——听歌记录允许偶尔漏一条，
  不值得为它维护持久化队列。token 留空时整条链路不启动。

## 五、macOS 系统媒体控件（新）

媒体控件此前只有 Linux MPRIS 和 Windows SMTC，Mac 上触摸栏、耳机键、
控制中心全是空的。本版新增 **Now Playing** 后端（souvlaki /
`MPRemoteCommandCenter`），复用现有 `media_session` 快照与命令层 ——
播放 / 暂停 / 上下曲 / 跳转进度 / 封面与元数据全部接通，
`[integration] now_playing = true`（默认开）可关闭。

这是首次接入，**尚未在真实 macOS 机器上验证过**；CI 会照常构建两个 macOS
target，遇到控件不响应或不显示请开 issue 带上 `voicefox.log`。

## 六、频谱可视化按平台门控

频谱采集只认 `parec` / `pw-record`（PipeWire/Pulse 监视流），
Windows / macOS 上按 `w` 只会得到「频谱可视化启动失败」。现在非 Linux 平台
按 `w`（或配置了 `visualizer = "bars"` 启动）会明确提示
「频谱可视化仅支持 Linux」，不再假装失败。

## 七、兼容性与升级

- 配置**无需手工迁移**：`source.js_first`、`integration.now_playing`、
  `integration.listenbrainz_token` 全部带 serde 默认值，旧配置照常加载，
  配置版本自动升到 17。
- JS 脚本缓存目录迁移是自动的、一次性的；两个目录同时有内容时以
  `voicefox/sources` 为准，旧文件留在原地。
- 「JS 音源优先」用户（依赖脚本解 VIP 曲目的）升级后如果发现某些歌改走了
  内置音源：这是预期行为，配置 `js_first = true` 即可恢复。
- 设置页「刷新远程歌单 / QQ 音乐同步」两行的说明从「双向增量」修正为
  「只读镜像」（网易云早已不是双向同步，文案这次才跟上）。

## 升级提示

直接替换二进制即可。三件事值得动一下配置或试一下：

1. Windows 上导入 JS 音源失败过的：更新后重试，失败信息会带 Node stderr；
2. 依赖 JS 音源的用户：按需加 `[source] js_first = true`；
3. 想记录听歌的：`[integration] listenbrainz_token` 填上 token，
   QQ 音乐用户：设置（`8`）→「账号与扫码」登录 QQ 后按 `Q` 拉取歌单镜像。
