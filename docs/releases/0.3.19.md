# VoiceFox 0.3.19

## 版本概览

这次更新集中在**交互系统**：把「鼠标事件 → 命中测试 → 组件 → 动作」「右键菜单」
「可拖拽分割布局」「可调整列宽的表格」这四件事，从原先各页面各写一套
收敛成项目级共享机制，并修掉由此产生的一批**点不准 / 差一行 / 拖了没反应**的缺陷。

同时修掉两个会静默丢数据的问题：**0.3.12 起旧数据目录读不到**（收藏、历史、下载记录、
播放会话），以及**播放状态被空队列误删**。

数据目录修复对老用户是行为变更：首次运行 0.3.19 时，旧目录里**目标位置不存在**的文件
会被迁移过来（已存在的新文件不会被覆盖）。

---

## 一、数据安全（本次重点）

### 修复：0.3.12 起旧数据目录的数据一直读不到

0.3.12 把数据目录从 `~/.config/voicefox/data` 改成 `~/.local/share/voicefox`
（Windows 为 `%APPDATA%\voicefox`），但**迁移逻辑只写在 `runtime/src/storage.rs`**，
而 app 实际编译的是 `app/src/storage.rs` —— 两份 1900 行的拷贝早已各自演化
（一份有锁外落盘、另一份有迁移），于是升级后：

- 收藏、历史、自定义歌单、下载记录、`playback_state.json` 全部留在旧目录，读不到；
- 新目录里一切从零开始，用户看到的就是"收藏没了、歌单没了、播放列表空白"。

现在只保留一份实现（app 侧改为对 `voicefox_runtime::storage` 的再导出），
并补上**逐文件补迁**：目标缺失才迁移，已存在的新数据一律不覆盖，重复调用幂等。
迁移挂在 `default_data_dir()` 的 `Once` 上，`Storage`、下载记录、远程缓存拿到的是同一路径。

### 修复：播放状态被"空队列"误删

`persist_playback_session()` 原本在队列为空时直接**删除**会话文件。于是
「打开 → 没播放 → 退出」这条最常见的路径会把上一次保存的播放状态抹掉，
表现就是"播放状态从来没保存过"；而且它会销毁现场，事后无法排查。

现在队列为空时**什么都不做**，只有用户显式清空队列（队列页 `Shift+D`）才调用新增的
`forget_playback_session()` 丢弃会话。

### 修复：会话文件解析失败被静默丢弃

`load_playback_session()` 原先用 `.ok()?` 吞掉反序列化错误。现在改为**告警 + 改名隔离**
（`playback_state.json.corrupt-<时间戳>`），保留现场，便于定位是哪种数据写坏了。

### 修复：半截的列配置会让程序起不来

`TableColumnConfig` 缺 `#[serde(default)]`，而这一节是用户可手写的：只要
`[[ui.table_columns.queue]]` 少写几个字段，整份 `Config` 反序列化失败 →
`main` 里的 `?` 直接让程序退出。现在补上 `serde(default)`，并在读取时做一次校正：

- `min_width > max_width`（会让 `Ord::clamp` panic）→ 夹成合法区间；
- `width = 0`（列会静默消失）→ 夹进 `[min_width, max_width]`；
- 空 `key` → 丢弃该条目。

## 二、鼠标交互统一

### 新增：`PanelRows` 行账本

以前每个页面在渲染里用游标递推行位置，在命中里**再算一遍**，漏记一行就整体错位。
现在把「过滤行 → 工具行（音源条等）→ 表头 → 列表」算一次，渲染与命中取同一份结果。

### 修复：Favorites 点击恒定选中下一首

渲染画了「过滤行 + **音源条** + 表头」三行，命中只按两行记账，**恒差 1 行** ——
点第 N 行选中/播放第 N+1 行，右键也偏一行。该缺陷在 0.3.19 之前的所有版本都存在。

### 修复：History「按了过滤键但还没输入」时差一行

渲染用 `filter.is_active() || !query().is_empty()`，命中只有 `!query().trim().is_empty()`。
现在过滤行是否可见统一走新增的 `ListFilter::is_visible()`，渲染与命中不可能再分叉。

### 修复：LocalMusic 命中区比渲染多一行

过滤条可见时命中高度没有减掉那一行，点面板下边框会选中一首屏幕上没有的歌。
顺带修掉旧实现"底部一行永远用不到"的浪费。

### 修复：Details 页点击整体偏移约 8 行

派发层一个传整屏 `area`、一个传内容区（差 7 行），页内又一处内缩基准不同（再差 1 行）。
现在两端共用同一个矩形与同一份内缩。

### 修复：队列过滤生效时右键指向错歌

左键按"过滤 / 未过滤"分流，右键却无条件用未过滤下标、还配着过滤视图的滚动偏移。

### 修复：音源标签条点不准

渲染前缀 `" 音源："` 实际显示宽度是 **7** 列（含全角冒号），命中按 4 列估算，
且每项还多算 1 列 —— 漂移随位置累积，点左边标签会选中隔壁音源。
现在渲染与命中共用 `tab_rects()`，覆盖 Search / 排行榜 / 歌单 / 收藏四处。
原单测断言的是那套错位算术，已重写为"标签条上任意可见列都必须命中它自己"。

### 修复：拖拽状态残留导致整页点不动

鼠标只在内容区内派发，在标签栏/侧边栏/进度条上松开左键时页面收不到 `Up`；
拖拽中切页、终端 resize 同理。残留状态会让该页后续鼠标事件被拖拽分支永久吞掉。
现在切页 / 内容区外抬起 / resize 三处统一收尾。

### 其它

- 5 个页面的滚轮加上区域判定：光标停在封面、歌词或空白处滚轮不再带动列表选中。
- 扫码登录 / 同步浮层是模态的，键盘分支早已拦截，鼠标分支此前漏了 —— 浮层在屏上时
  点标签栏会切页、点进度条会 seek、点通知会开外链。现已一并拦下。
- 下载面板支持**左键点面板外关闭**（此前只能用键盘关）。

## 三、右键菜单统一

`SongContextMenu` 从"歌曲专用、三层写死"改成**通用菜单**：

| 能力 | 之前 | 现在 |
|---|---|---|
| 层级 | 固定 3 层枚举 + 3 个固定 Vec | `Vec<MenuLevel>` 栈，任意层级 |
| 动作 | `SongMenuAction`（歌曲专用） | `MenuAction { Song, Column, Submenu, Back }` |
| 返回上级 | 单向门（Esc 直接关掉整个菜单） | 子菜单自动带「← 返回上级」，Esc 逐级返回 |
| 禁用项 | 无 | `MenuItem::disabled()`：跳过选中与激活，muted 渲染 |
| 提示列 | 无 | `with_hint()` 右端显示（如 `Esc`、`必显`） |

### 新增：无鼠标环境的菜单入口

新增动作 `ListContextMenu`，默认键 **`x`**（7 个歌曲列表页，可自行改键）。
右键与键盘走**同一条目标解析路径**（`MenuHitSource::{Mouse, Selected}`），
因此不会出现"右键能用、键盘不能用"或两边命中不一致。

### 修复：`x` 键在设置页不占用

设置页没有歌曲列表，不绑定该键。

## 四、可拖拽布局（Splitter）

### 新增：统一的 Splitter 机制

抽出 `components/splitter.rs`：`SplitAxis` / `DividerHit`（把**方向**变成入参）/
`Splitter<T>` 状态机（begin / drag / effective / commit / cancel）/ `clamp_ratio`
（带 NaN 防护）/ `ratio_within`。三个页面原先各写一套同构实现，现在共用。

### 修复：排行榜 / 歌单页分割条方向误判

`PageChunks` 没有方向字段，于是横、竖两个命中判定**串行无条件求值**：
窄布局下"每行最右一列"、宽布局下"面板最后一行"都会被当成分割条抓走，
正常点击被吞，而且启动的是方向错误的拖拽（画面完全不动）。
现在布局结构带 `wide` 标志，方向由布局决定，并只绘制当前方向的那条线。
歌单页另外补上了此前**完全缺失**的 Esc 取消。

### 新增：面板比例持久化

新增 `ui.pane_ratios`，按页面 key 存多层比例，例如：

```toml
[ui.pane_ratios.queue]
wide_columns = 0.4
narrow_queue = 0.6
```

队列、排行榜、歌单、设置四个页面拖出来的尺寸都会被记住，重启后恢复。
此前比例只存在内存里，重启即回默认。

### 新增：设置页可拖拽分割

设置页原先面板比例是硬编码的 `34/32/34` 与 `60/40`，现在可拖拽、可持久化、Esc 可还原。
**默认值与旧硬编码逐像素一致**（有回归测试断言实际列宽），不改变既有观感。

## 五、表格列

### 列宽可调整并持久化

队列、搜索、排行榜、歌单、收藏、历史、本地音乐七处歌曲列表共用同一份列模型
（`TableColumnConfig` + `compute_layout` / `adjust_widths` / `find_boundary`），
拖动表头分隔线即可调整；列宽按页面 key 存进 `ui.table_columns`。

### 修复：拖拽结果被渲染每帧覆盖

7 个页面的渲染路径每帧**无条件**从配置重载列宽，把 `handle_mouse` 刚算出的值
在同一帧覆盖回旧值 —— 表现为"拖拽时列宽纹丝不动、松手提交的还是原值"，
等于整个功能没接上。现在拖拽期间以页面状态为准。

### 新增：列之间的视觉区分

同色的空格填充让相邻两列糊在一起。现在：

- 每列之间插入 `│` 分隔符（`overlay1`，选中行底色上也可见）；
- 表头整行铺 `surface0` 色带 + 加粗，与数据行分层；
- `#` 与 `时长` 按数字右对齐。

分隔符占用的是该列**已有 padding 里的 1 个字符**，因此**总宽度严格不变**
（有强制不变量测试覆盖 24~200 列），列宽配置与命中测试完全不受影响。

### 新增：表头右键「列设置」

```
 列设置
 ✓ #                        ← 点一下隐藏 / 显示
 ✓ 歌曲   [必显]            ← "歌曲"列固定必显（禁用项）
 ✓ 歌手
 ...
 自动调整列宽               ← 按当前列表内容测量，超宽时从余量最大的列回收
 恢复默认列宽               ← 同时恢复了此前"有处理体、零触发入口"的 ResetColumnWidths
```

## 九、本次版本重点

这一版的核心不是加功能，而是**把四套各页面自写的交互收敛成共享机制**：
命中几何、右键菜单、分割条、表格列。收敛之后，此前散落在各页面的
"差一行 / 点不准 / 拖了没反应"才暴露出共同的结构性成因（渲染与命中各算一遍、
布局结构缺方向标志、拖拽状态没有兜底清理），并一次性修掉。

数据安全两项（旧目录迁移、播放会话误删）优先级最高：它们属于"用户没报错但数据已经没了"
的类型，因此改成要么完整成功、要么明确告警并保留现场。
