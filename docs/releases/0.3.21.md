# VoiceFox 0.3.21

## 版本概览

这一版修掉两个**看得到、说不清**的老问题，并把封面缓存这块重复实现收成一份。

- **逐字歌词不再把时间轴源码当歌词显示**：部分音源把 QRC/YRC 逐字歌词塞进 `lyric`
  字段，而 `lxlyric` 为空，于是 `[0,4810]<0,210,0>You …` 被整段当纯文本渲染出来。
- **封面为什么是空的，现在能自己查了**：封面图协议在 kitty 上除了 `sixel`，
  **`iterm2` 也一样画不出来**（kitty 会静默丢弃 `OSC 1337;File=`）。旧行为是照发、
  然后留一个空框；现在只发本终端画得出的协议，并在设置页那一行直接写出原因。
- **本地与在线封面共用一份缓存实现**，缓存文件名改用 sha256，512 的淘汰预算
  也统一到整份缓存。

追加的体验改动：远程歌单改用**独立窗口**浏览（可排序 / 过滤 / 回车跳转）、
面板布局恢复默认有了**一键快捷键** `Ctrl+G`、设置页不再逐行重复 `[Enter]`、
`[·]` 占位。

## 一、修复

### 逐字歌词被当成纯文本显示

少数音源（尤其是 JS 自定义音源）把逐字歌词写进 `lyric`，而约定字段 `lxlyric`
为空或只有时间头行。解析器原先只在 `lxlyric` 里找逐字歌词，找不到就**无条件**走
"纯文本兜底"，于是带时间标记的源码被原样显示。

现在：

- 逐字歌词同时从 `lxlyric` 与 `lyric` 解析并合并去重，谁有内容用谁；
- 新增 `looks_like_karaoke` 判定：带逐字标记的内容**绝不**再按纯文本兜底；
- 新增 `normalize_karaoke_text`：统一处理 `LyricContent="…"` XML 包装、`\n` / `&#10;`
  转义、KRC 风格的 `|` 分行以及 `"/>` 收尾残留；
- 只有时间头没有正文的空行会被丢掉。

回归用例直接取出问题那首歌的片段：显示文本为 `You ready Yo`。

### 封面：kitty 上把画不出的协议也发给终端

`kitty` 只实现自己的图形协议：既不支持 `sixel`，**也不支持 iTerm2 的
`OSC 1337;File=`**。两种配错的表现不同：

| 配错 | 表现 |
|---|---|
| `sixel` | 整幅载荷被当文本打印（满屏 `?`） |
| `iterm2` | kitty **静默丢弃**该序列 —— 封面区只留一个空框 |

后者最难自查：因为应用认为"有图可画"，占位文字被跳过，屏幕上什么都没有。
本次把终端能力收敛成单一判定点 `CoverCapabilities`：

- **运行期**：`CoverRenderer::detect` 据它决定真正生效的协议（配错才纠正 + 告警）；
- **界面**：设置页 `Shift+P` 只在**本终端画得出**的协议之间循环（kitty 下
  `kitty → halfblocks`），该行的值会显示成
  `iterm2（本终端不支持该协议，已改用 kitty；可选 kitty / halfblocks）`；
- 封面占位文字不再在"无地址"和"协议画不出"两种状态下都渲染成空行，现在分别显示
  `音源未返回封面地址` / `封面无法显示（终端协议不支持）`；
- 封面错误行改为按**显示宽度**截断（原先按字符数，中文会撑出封面框）。

> 既有配置无需改动；显式写 `ui.cover_protocol` 仍然优先，只是不可能成立的组合会被纠正。

### 封面缓存：合并重复实现，缓存键换成 sha256

本地文件的内嵌封面缓存与远程封面缓存原本各有一份完整实现（目录 / 命名 /
`.part` 临时文件 / 解码校验后原子 rename），而它们在 Linux 上解析到**同一个目录**
`~/.cache/voicefox/covers` —— 也就是说 `runtime` 的 sweep 已经在按自己的 512 预算
淘汰 `lx-source` 写进去的文件。现在抽出 `lx_source::cover_cache`：

- 目录、内容哈希、尺寸探测、原子写入与淘汰规则只有一处实现；`CACHE_LIMIT = 512`
  是**整份缓存**的预算；
- 缓存键从 `DefaultHasher` 换成 `sha256`：std 明确声明其算法不保证跨 Rust 版本稳定，
  换工具链会让整份缓存失配（`sha2` / `hex` 本就在依赖树里，不新增依赖）；
- 封面下载复用 `lx-source` 的 `SendWithRetry`：重试只包住**发送阶段**，解码校验留在
  外面 —— 4xx 与损坏图片不再各重试三次，失败提前约 450ms 显现。

## 二、歌单：账号歌单与音源推荐歌单拆开并存

登录网易云后，歌单页的网易云入口原先被远程缓存整个顶掉（"缓存就绪时以缓存为唯一
数据源"），推荐歌单因此**完全没有入口**。现在拆成两个并存的作用域：

| 入口 | 数据源 | 说明 |
|---|---|---|
| `我的歌单` | 远程缓存（只读镜像） | 只有刷新过且缓存非空时才出现，不发网络请求 |
| `网易云` | 音源自己的歌单接口 | 恢复成推荐 / 热门歌单 |

进入歌单页时按缓存 generation 重建入口，因此刷新完之后**不用重启**就能看到
「我的歌单」出现或消失。音源接口失败但本地有账号歌单时会降级给缓存，不会再停在
空列表 + 报错。

### 远程歌单改用独立窗口（`v`）

22 个远程歌单原先挤在「设置 · 账号与扫码」面板底部：名称被截断、数量对不齐、
一屏塞不下、也没法找。现在按 `v` 打开一个居中窗口：

- 定宽两列（名称截断对齐 + 数量右对齐），可滚动并显示 `12 / 22` 位置；
- `s` 按名称 / 歌曲数排序，`/` 过滤（复用列表页统一的 `ListFilter`：Esc 结束输入、
  保留条件，再按一次 Esc 关窗）；
- `Enter` 跳到「歌单 · 我的歌单」并定位该歌单 —— 窗口只负责看清与找到，播放 / 入队 /
  收藏仍在歌单页里做；
- 模态独占键鼠，窗口开着时按 generation 变化就地刷新；缓存为空也能打开并给出
  "先去刷新远程歌单"的引导。

## 三、界面

- **面板布局恢复默认有了一键快捷键 `Ctrl+G`**：等价于表头右键菜单里的
  「恢复默认面板布局」，按当前页面生效（队列的左右栏与封面/歌词分栏、榜单与歌单的
  列表宽度、设置页的分类栏与内嵌列表高度）。此前它只存在于右键菜单里，无鼠标环境
  按不到。**故意不用 `Ctrl+Shift+R`**：多数终端把 `Ctrl+Shift+<字母>` 报成与
  `Ctrl+<字母>` 相同的字节，拿不到 SHIFT 修饰位，按下去会变成"强制重绘"。
- **设置页不再逐行重复 `[Enter]`**：Enter 激活这条共性写在面板标题里，行内只留安静的
  `[·]` 占位，只有真有专属快捷键的行（封面协议 `[S+P]`）才写出键。
- **定宽 / 截断助手收敛到 `components/text.rs`**：`pad_display` / `pad_display_left` 与
  既有的 `truncate_width` 配成"定宽列"原语，六处各自手写的实现改为复用。顺带修掉
  `truncate_display` 的补齐 bug —— 截断分支直接返回而不补齐，
  `truncate_display("晴晴晴", 4)` 只有 3 列，而三个调用点都靠它对齐。

## 四、内部整理

- 删除没有生产消费者的 `nucleo-matcher` 依赖（原先只被一个 benchmark bin 用到，
  而那个 bin 每次构建都编）。列表过滤保持 `contains` 语义统一，避免"模糊匹配把
  `AP` 匹配到 `Alpha`"被读成 bug。
- `PlaybackEffects` 增加 `cover_url_is_usable`，播放路径与 app 侧原先各写一遍的
  "封面地址解析"统一为 `resolve_cover_url`。
- 新增两个 `#[ignore]` 的真实文件验证，需要曲库时手动跑：
  `lx-source` 的 `embedded_cover_survives_the_read_path` 与 `voicefox-runtime` 的
  `local_cover_reaches_the_cover_service`。

## 五、兼容性与已知取舍

- 配置与数据无需迁移。封面缓存文件名口径会变化（sha256），旧文件由 512 预算自然
  淘汰，表现为"封面首次重新下载一遍"。
- 封面协议显式配置仍然优先；`sixel` / `iterm2` 在 kitty 终端上会被纠正为 kitty 协议
  并告警（这是终端能力决定的，不是配置错误检测）。
- 设置页 `Shift+P` 看不到 `sixel` / `iterm2` 选项是**有意**的：它们在本终端画不出来。
  需要显式配置可在 `config.toml` 里手写。

## 升级提示

直接替换二进制即可。若封面区仍是空白，先看启动日志里是否有
`cover protocol = … 在本终端不被支持，已改用 …`，或检查设置页「封面协议」行的提示。
