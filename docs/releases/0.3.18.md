# VoiceFox 0.3.18

## 版本概览

本次更新集中在三块：**网易云歌单**、**中文输入法**、**主题色**。

其中网易云歌单是一条行为变更：歌单不再复制成本地歌单，而是作为**只读远程集合**
读进本地缓存；同时修掉了「收藏来的歌单只显示 20 首」这个数据截断问题。

另外修掉了输入法候选框上下跳动（[#42](https://github.com/emoeem/voicefox/issues/42)）、
主题色写错导致启动崩溃、以及一批在其他模块里核实过的缺陷。

## 网易云歌单（本次重点）

### 修复：收藏来的歌单只加载前 20 首

`api/v3/playlist/detail` 的 `playlist.tracks` 字段对**非本人创建的**歌单只返回前
20 首，完整列表在 `playlist.trackIds`，而且 `n` 参数已被服务端忽略（实测
`n=1000` 与 `n=100000` 都只给 20 首）。现在改为以 `trackIds` 为准，再分批用
`api/v3/song/detail` 补全歌曲详情。

实测同一账号 23 个歌单：修复前合计取回 **736 首**，修复后 **3972 首**（等于声明总数），
其中「现代风 帅气」716→716、「「电音」你一定听过的万评电音精选」523→523。

链接直解（`wy::parse::fetch_playlist`）原先读同一个字段，也一并改为复用同一条路径。

### 修复：红心歌单识别

原先按名称匹配「我喜欢」，而官方名称是「我喜欢的音乐」，永远匹配不上，导致收藏
同步直接失败。现在优先使用 `specialType == 5` 识别，用户改名后依然有效；名称匹配
只在响应缺少该字段时作为回退。

同时红心歌单不再作为普通歌单重复出现（此前它会以两种身份各进缓存一次）。

### 改进：只读远程集合缓存

- 歌单不再复制成本地歌单，也不再向远端推送；歌单页在缓存就绪时以缓存为数据源。
- 缓存按 id 增量合并；只有远端结果完整时才整体替换，远端删掉的歌单才会消失。
- 只要有一个歌单没拉到，就退化为增量合并，失败歌单保留缓存里的旧数据，并在预览
  与结果页里列出是哪几个。
- 缓存落盘到数据目录下的 `netease_collections.json`，重启后不再是「热门歌单」。
- 预览页不再声称会把本地歌单上传到网易云（原先的文案与行为不符）。

### 修复：触发频控时的处理

请求过密时网易云返回 **HTTP 200 + `code=405`、「操作频繁，请稍候再试」**。旧实现用
`unwrap_or_default()` 把它当成空歌单写进缓存，属于静默丢数据。现在识别该业务码并
按 600/1200/2400/4000ms 退避重试，其他业务码直接报错而不是吞掉。

同时预览与执行原先各拉一遍全库（约 52 次请求，正是触发频控的原因），现在合并为
一次拉取。

### 其他

- `get_user_playlists` 增加自动翻页，歌单超过 100 个不再被静默截断。
- 登录风控识别恢复：轮询收到「请完成验证操作」「操作频繁」时保持轮询，不再误判成
  登录失败并中断二维码页面。
- 新增会话有效性探测 `wy::login::refresh()`；同步前会预检，失效时直接提示重新扫码。
  公开接口没有可用的续期端点（`login/token/refresh` 返回 400、`login/refresh` 返回
  404），所以它只做探测、不延长会话。
- 扫码登录主机按 `interface.music.163.com` → `interface3.music.163.com` →
  `music.163.com` 顺序回退，避免单个主机抽风就表现为「生成二维码失败」。
- 设置页账号面板里 `q` 不再被「同步 QQ」占用（改为 `Shift+Q`），恢复全局退出键。
- QQ 音乐尚未接入该模式，按键会明确提示暂不支持。

## 中文输入法（#42）

在搜索框、筛选栏、各输入弹窗里输入中文时，候选框会在输入框与底部状态栏之间上下
反复跳跃。

成因：输入法的候选框跟随**终端光标**，而 ratatui 采用差分渲染 —— 不设置
`Frame::cursor_position` 时，它只发「隐藏光标」序列、**不移动光标**，于是光标停在
**本帧最后一个变化的单元格**上。打字时变化的行在搜索框与状态栏之间切换，候选框
就跟着来回跳。英文输入法没有候选框，所以看不出问题。

现在每个文本输入在渲染时登记插入点，主循环每帧显式设置光标位置，光标只由「焦点在
哪个输入框」决定，与差分结果无关。共覆盖 11 个文本输入：搜索框、队列筛选、收藏/
历史/本地筛选栏、歌单搜索、自建歌单命名，以及设置里的 6 个输入弹窗。

配套调整：

- 输入框的插入点改用终端自己的光标表示，去掉原先手绘的 `█` 字符（否则会和终端光标重影）。
- 补上两个此前**没有可见输入框**的输入：歌单搜索的关键字现在显示在标题里；设置里的
  下载目录 / 文件名模板新增输入弹窗（此前只写状态栏提示，用户看不到自己输入的内容）。
- 设置里 6 个输入浮层的重复渲染代码收敛为一个函数。

## 主题色

### 修复：背景写死、改不动

默认背景是硬编码的 `#1e1e2e`，而且颜色解析器只认 10 个 ANSI 名字与 `#rrggbb`，其余
值一律静默回退。所以写 `base = "default"`（或 `reset` / `transparent` / `none` /
`terminal`）都不生效，看起来就是"背景写死、不跟随终端"。

现在支持四种写法，并让「跟随终端」真正可用：

| 写法 | 例子 |
|---|---|
| 跟随终端（`Color::Reset`） | `"default"` / `"reset"` / `"terminal"` / `"none"` / `"transparent"` / `"-"` |
| 16 色名 | `"red"`、`"light_blue"`、`"bright-blue"`、`"dark_gray"` |
| 十六进制 | `"#cba6f7"`、三位缩写 `"#abc"` |
| ANSI 256 色号 | `"236"`、`"color236"` |

默认配色仍是 Catppuccin Mocha（行为不变）；把 `base` 设成 `default` 即可让背景透出
终端主题。面板仍使用各自的 `surface*` / `mantle` / `crust` 底色，所以透明只作用于
最底层。

### 修复：主题色写错会直接崩溃

旧解析器用 `value.len() == 7`（**字节**长度）判断十六进制色值，然后直接切
`&value[1..3]`、`&value[3..5]`、`&value[5..7]`。像 `base = "#abc晴"` 这种值字节长
正好是 7，会切在汉字中间，在非字符边界上 panic —— 而主题色每帧都在解析，等于一启动
就崩。现在先确认整串都是 ASCII 十六进制字符再切，识别不了的值回退到默认色。

### 改进：写错颜色会提示

`parse_value` 认不出来的值仍会回退，但配置加载阶段会集中给出
`主题色 theme.xxx 无法识别，已回退到默认色` 的日志，不再是完全静默。

### 清理

删除 `ThemeConfig::use_dark`：该字段只被声明和赋默认值，全仓库没有任何地方读取它，
`config.example.toml` 却把它写成可用选项。真正实现浅色主题需要区分"用户显式指定
`#1e1e2e`"与"这是写进配置文件的默认值"，属于另一项改动，本次先移除这个误导性配置。

## 其他缺陷修复

以下问题均经过代码复核确认：

- **歌词回退阻塞播放**：无词歌曲会串行尝试最多约 275 个候选、每个带独立超时，可阻塞
  数分钟。现在限制为 8 个候选并加 15 秒总预算，最坏情况从数分钟降到 ≤15 秒。
- **收藏写入阻塞渲染**：`add_favorite` / `remove_favorite` 等 8 个写方法原先在持有写锁
  期间完成 JSON 序列化 + fsync + rename，渲染路径读同一把锁会被一起阻塞。现在锁内只做
  变更与快照，落盘移到锁外。
- **锁中毒导致 panic**：`load_history`、`custom_playlist`、`custom_playlist_choices`、
  `notification_timeout` 使用 `.read().unwrap()`，与其他位置的
  `unwrap_or_else(|e| e.into_inner())` 不一致，一处锁中毒就会让 TUI 崩溃。
- **QQ 歌单写入可能删错歌**：`ids` 用 `filter_map` 构建（可能少项），`types` 用
  `songs.len()`（全量），两者按位置配对，只要有一首歌缺少 `songId` 就会错位，却仍
  返回成功。现在两者由同一份过滤后的列表派生；添加歌曲一侧同样问题一并修复。
- **汽水音源越界分配**：直接用下载文件里的计数做 `vec![..; count]` /
  `Vec::with_capacity(count)`，损坏或恶意文件可触发数 GB 分配并 abort。现在按缓冲区
  大小钳制。
- **队列拖拽排序不生效**：`Up` 分支先清空 `dragging`，随后的应用判断永远匹配不上。
- **音源选择弹窗点击错位**：渲染按滚动偏移裁剪，命中的却用屏幕行号直接当索引，
  列表滚动后点谁都不是谁。
- **排行榜错误响应重置光标**：`self.selected = 0` 写在 `match` 之外，无关的过期响应
  也会把光标弹回顶部。
- **本地音乐重复深拷贝**：每次扫描整库深拷贝 2~3 次，现在去掉全库克隆与重复克隆。
- **删除死代码**：`core/src/model/keybinding.rs`（610 行，无任何引用，与
  `core/src/keybinding/mod.rs` 是两份会分叉的版本）；
  `Storage::sync_playlist_mapping` / `set_sync_playlist_mapping`（随本地复制模式一起失效）。

## 本次版本重点

优先保证**数据正确性**：歌单曲目数、缓存合并语义、频控与锁的处理都属于"出错会静默
丢数据"的类型，因此这一版把这些路径改成要么完整成功、要么明确报错并保留旧数据。

输入法与主题色的修复都属于"用户看得见但以前说不清"的问题：候选框跳动和背景不跟随
终端，现在都能给出明确成因与可配置的解法。
